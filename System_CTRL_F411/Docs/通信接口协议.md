# F411 主控通信接口协议

本文描述 `System_CTRL_F411` 当前固件的实际通信行为。主控分别轮询电机驱动板和触觉采集板，并通过 USB CDC 与 PC 交换二进制数据；这三条链路的消息格式并不相同。

## 1. 接口与轮询

| 链路 | 主控引脚 / 接口 | 格式 | 作用 |
|---|---|---|---|
| PC | USB_OTG_FS，USB CDC 虚拟串口 | 二进制字节流 | 接收电机命令，上传电机和触觉数据 |
| 电机 | USART1：PA9 TX、PA10 RX | 460800 bit/s，8N1 | 双线异步、17 个驱动板轮询 |
| 触觉 | USART2：PA2 TX、PA3 RX | 460800 bit/s，8N1 | 双线异步、12 个采集板轮询 |

串口 TX 使用 DMA，RX 使用循环 DMA 和 IDLE/半满/全满事件。USB CDC 的主机串口波特率设置不改变 USART1/2 的波特率。

电机和触觉各自有一组共享总线：主控 TX 连接各板 RX，主控 RX 接收各板 TX，所有板共地。软件轮询不能代替电气仲裁：多个推挽 TX 直接相连会争用，电机板须有空闲高阻或外部隔离及适当的空闲电平。触觉板固件在不发送时将 TX 置为高阻。

### 1.1 电机 ID

| ID | 关节 | ID | 关节 |
|---:|---|---:|---|
| 0 | 拇指 CMC_FE | 9 | 中指 MCP_AA |
| 1 | 拇指 CMC_Rotation | 10 | 中指 MCP_FE |
| 2 | 拇指 MCP_FE | 11 | 中指 PIP_FE |
| 3 | 拇指 PIP_FE | 12 | 中指 DIP_FE |
| 4 | 拇指 DIP_FE | 13 | 无名指 MCP_AA |
| 5 | 食指 MCP_AA | 14 | 无名指 MCP_FE |
| 6 | 食指 MCP_FE | 15 | 无名指 PIP_FE |
| 7 | 食指 PIP_FE | 16 | 无名指 DIP_FE |
| 8 | 食指 DIP_FE | | |

板卡 ID 不是 `finger * 4 + joint`。每块驱动板必须单独配置唯一 ID。`0xFF` 仅表示 PC 下发的禁用广播，不是板卡 ID。

### 1.2 调度和超时

- 电机 TIM3 周期 50 ms，TIM4 标称槽间隔 2.5 ms；轮询 ID 0 在轮次开始时排队，ID 1～16 理想排队时刻为 2.5～40 ms。发送在主循环异步启动。
- 完整发送 10 字节请求约 217 μs，16 字节响应约 347 μs；应答计时从发送完成开始，超时 2 ms。若先前请求未完成或已排队，下一次 TIM4 不推进 ID；轮次因主循环、发送异常或中断延迟可能超期，**50 ms 不是硬实时保证**。缺失板在正常处理延迟下的理想结束时间约 42.217 ms。
- 触觉 TIM1 周期 50 ms，TIM2 槽间隔 4 ms；ID 0～11 理想发送时刻为 0～44 ms，下一个槽检查前一响应，末板在 48 ms 检查。有效响应要求板 ID 与当前轮询目标匹配。
- 不保证超时后才返回的迟到帧与新轮询安全共存；从板须限制响应延迟，并由实测校验整条链路。

## 2. PC ↔ 主控：USB CDC

### 2.1 PC 下发电机命令

PC 按字节流发送下面的 10 字节请求，允许拆分或合并 USB 包。所有多字节字段小端：

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 1 | SOF | `0xA5` |
| 1 | 1 | ID | `0..16`；`0xFF` 仅可用于 `DISABLE` |
| 2 | 1 | command | `0..7`，见下表 |
| 3 | 1 | sequence | PC 提供的序号，原样回显 |
| 4 | 4 | pData | IEEE-754 float32，小端 |
| 8 | 2 | CRC16 | 对偏移 0～7 计算，低字节在前 |

| 命令值 | 名称 | 参数 |
|---:|---|---|
| 0 | IMP_TAU | 目标力矩 |
| 1 | IMP_VEL | 目标速度 |
| 2 | IMP_POS | 目标位置 |
| 3 | IMP_K_P | 刚度 |
| 4 | IMP_K_D | 阻尼 |
| 5 | CAL_ZERO | 忽略，填 0 |
| 6 | ENABLE | 忽略，填 0 |
| 7 | DISABLE | 忽略，填 0 |

主控验证 SOF、ID、命令范围和 CRC，并将请求写入该 ID 的**最新命令表**，不是逐条发送的 FIFO。主控和当前驱动板不检查控制参数是否为有限数；PC 必须限制参数为安全的有限值。同一 ID 两条命令若都在下一次轮询前到达，后者覆盖前者；轮询时重复发送该 ID 当前记录，sequence 也保持不变。`0xFF/DISABLE` 更新全部 17 项，随后逐一单播，不直接转发广播帧。初始化时所有项为 `DISABLE`、sequence 为 0。

**重要限制：**`CAL_ZERO` 留在最新命令表中会每轮重复触发校零；新命令可能在某一轮发送前覆盖校零、增益或使能指令。因此执行校零及连续下发不同参数时不能假定每条指令恰好执行一次。PC 断开 USB 后，主控仍会继续周期发送最后命令；这会刷新驱动板的通信看门狗，不能依赖该看门狗检测 PC 断连。应在联调及控制前解决这些端到端策略问题。

### 2.2 主控上传给 PC

USB CDC IN 流混合下述两种完整二进制帧，上传顺序由到达和 USB 忙状态决定；USB 数据包边界不能作为应用帧边界，PC 须以帧头、固定长度和校验解析。

- 电机：`0x5A` 开头，16 字节，格式见第 3 节。主控只转发当前目标 ID、sequence 和 CRC 全部匹配的响应。
- 触觉：`0xFF 0x66` 开头，79 字节，格式见第 4 节。主控只转发校验正确且 ID 与当前目标相符的响应。

主控有有限 USB 发送队列（电机 17 帧、触觉 8 帧）；USB 长时间忙或未连接时队列会满，帧可能丢失，不能作为可靠消息队列。

## 3. 主控 ↔ 电机驱动板：USART1

请求帧与第 2.1 节相同。主控按 ID 单播，只有被寻址板应回传。响应固定 16 字节，小端编码：

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 1 | SOF | `0x5A` |
| 1 | 1 | ID | `0..16` |
| 2 | 1 | sequence | 请求序号回显 |
| 3 | 2 | pos | MA782 原始相对角度值，uint16 |
| 5 | 4 | Uvm | 母线电压 float32 |
| 9 | 4 | bdc_temp | 驱动板温度 float32 |
| 13 | 1 | status | bit 0：电机使能；bit 1：校零中；bit 2：零点有效 |
| 14 | 2 | CRC16 | 覆盖偏移 0～13，低字节在前 |

请求和响应均使用 CRC-16/CCITT-FALSE：多项式 `0x1021`、初值 `0xFFFF`、不反射、异或输出 `0x0000`。驱动板仅在合法目标帧时应答；`CAL_ZERO` 涉及 Flash 写入，`status.bit2` 可能保留此前的有效标志，不能单独证明本次校零成功。实际耗时、异常恢复和零点有效性须按驱动板协议及硬件验证。

## 4. 主控 ↔ 触觉采集板：USART2

触觉板 ID 为 `0..11`。轮询请求为 5 字节：`AA 55 01 ID CHECK8`，其中 `CHECK8 = (0xAA + 0x55 + 0x01 + ID) & 0xFF`。匹配 ID 的采集板发送 79 字节响应：

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 2 | SOF | `FF 66` |
| 2 | 1 | ID | 板卡 ID |
| 3 | 2 | counter | 帧计数，uint16，大端 |
| 5 | 72 | 数据 | 36 个 uint16 触觉值，逐值大端；当前从板由 ADC 数据换算得到 |
| 77 | 2 | CHECK16 | 偏移 0～76 所有字节累加后取低 16 位，大端 |

主控不修改有效触觉帧，直接通过 USB 上传。触觉与电机的多字节字段字节序不同，PC 必须分别解码。
