# 多传感器触觉监控与灵巧手电机控制上位机

该 Windows 桌面程序通过 STM32F411 的 USB CDC 虚拟串口接收触觉数据，默认同时展示 12 块 6×6 压阻触觉传感板，并提供 17 个电机驱动板的控制页面。

## 1. 触觉数据协议

F411 转发给 PC 的每个触觉帧固定为 79 字节：

| 字节位置 | 字节数 | 内容 |
|---|---:|---|
| 0～1 | 2 | 帧头 `0xFF 0x66` |
| 2 | 1 | 传感板 ID |
| 3～4 | 2 | 16 位计数器，高字节在前 |
| 5～76 | 72 | 36 个 ADC 值，每个值高字节在前 |
| 77～78 | 2 | Byte 0～76 的 16 位累加和，高字节在前 |

校验和为 `sum(frame[0:77]) & 0xFFFF`。程序将 USB CDC 当作字节流处理，不假设一次读取恰好返回一帧；完整帧校验后交给原触觉解析和显示。

## 2. 触觉界面

- 连接页提供 COM 端口下拉框、刷新和连接；
- 监控页按 3 行 × 4 列显示 12 块 6×6 传感板；
- 每块传感板显示 6×6 ADC 数值、在线状态、帧计数器、接收 FPS 和更新时间；
- ADC 热力图由白色渐变至红色，数字为黑色；
- 显示有效帧、校验错误和丢弃字节统计；
- 支持全局 ADC 固定减少值，自动记忆上次使用的 COM 端口和 Offset。

校准显示公式：`显示值 = max(0, ADC原始值 - Offset)`。

默认传感板 ID 配置位于 `main.py`：

```python
BOARD_IDS = tuple(range(12))
```

对应 ID 为 `0x00`～`0x0B`。

## 3. 电机控制界面

窗口顶部菜单可在“触觉传感”和“电机控制”页面之间切换。电机页每行一个手指，拇指 5 列，其他手指各 4 列；共 17 个独立关节卡片，目标范围为 -180°～+180°，初值为 0°。每张卡片可通过滑块或数值输入设置目标角度，输入精度为 0.1°，两种控件同步；卡片同时显示最新回传的实际角度、母线电压和驱动板温度。

电机 ID 与关节对应（每行按从左到右的顺序）：

| 手指 | ID 与关节 |
|---|---|
| 拇指 | 0 CMC_FE, 1 CMC_Rotation, 2 MCP_FE, 3 PIP_FE, 4 DIP_FE |
| 食指 | 5 MCP_AA, 6 MCP_FE, 7 PIP_FE, 8 DIP_FE |
| 中指 | 9 MCP_AA, 10 MCP_FE, 11 PIP_FE, 12 DIP_FE |
| 无名指 | 13 MCP_AA, 14 MCP_FE, 15 PIP_FE, 16 DIP_FE |

电机页顶部将串口状态、连接/断开、全部电机使能/失能、全部电机零点标定和运行状态放在同一行。

- 触觉和电机共用同一个 COM 端口及串口接收线程；
- “使能全部电机”按 ID 顺序逐板发送 17 条单播命令；全部发送后等待约 100 ms，让桥接板应用命令，再开始位置轮询；
- 使能期间每 50 ms 发送一组 17 电机的最新滑块目标。F411 在各自的 2.5 ms 槽位轮询电机板，PC 将一组目标作为一个 USB 批次发送；
- “失能全部电机”按 ID 顺序逐板发送 17 条单播失能命令；
- “标定全部电机零点”会先弹出安全确认，然后逐板发送失能命令，等待约 100 ms 后再逐板发送 `CAL_ZERO`；这段等待时间不能证明每块板都已应用失能命令；
- 每次校零操作向 ID 0～16 各排队一次 `CAL_ZERO`，不等待逐板响应；最后一条排队后等待约 50 ms，然后按 ID 循环排队 `DISABLE`：相邻 ID 约 3 ms，一轮结束后间隔约 50 ms 再开始下一轮。约 350 ms 后结束响应统计，轮询持续到重新使能、开始新一轮校零或串口断开。排队失败时会重试失能；尚未发送的旧失能轮询在重新使能前会被清除，已开始发送的无法撤回；
- 状态栏显示与本次 `CAL_ZERO` 或后续 `DISABLE` 请求的 ID 和序号匹配的响应数量及 `ZERO_VALID` 数量；未响应的 ID 另行列出，统计不能证明本次校零成功。USB 队列入队不代表主控或驱动板已收到，50 ms 从入队开始，不能保证驱动板恰好执行一次或一定执行；
- 零点校准会擦写驱动板 Flash，必须确保手部静止、无人受压且处于安全机械位置；上位机会先发送失能命令，但不能仅凭发送成功确认所有板已失能；
- 关闭串口前尽可能发送广播 `DISABLE`。协议规定广播命令不回传，因此无法确认每块板均已执行。

位置轮询时序为 Windows GUI 的尽力调度，不是硬实时保证。Qt 定时器、Windows 调度、串口转发与对端响应延时均会影响实际周期。

### 安全和校零警告

**不要把 PC 断连或停止 PC 发送当作停机。** 主控会周期重发每个 ID 的最后命令；若驱动板通信看门狗已启用，只要驱动板仍收到有效单播，看门狗就会被刷新；看门狗关闭时更不能依赖其停机。PC 断线、崩溃或发送失败后，旧目标可能继续执行。正常关闭只是尝试发送广播 `DISABLE`，不保证被主控接收或各板执行。必须使用独立的可靠急停或电源切断方式，并确认机构确已停止。

**同一 ID 的命令会互相覆盖。** 主控只保存每板的最后一条命令，不是逐条必达队列；快速发送的 `ENABLE`、`CAL_ZERO`、`Kp`、`Kd` 和目标命令可能在下发前被后一条替换，并非发送成功即已执行。

**`CAL_ZERO` 可能被重复执行。** 在主控收到替换命令之前它会按轮询重发；驱动板不按序号去重，可能重复校零和擦写 Flash。延迟、丢包或 PC 断连可使替换失败或过早覆盖校零，因此不能保证命令恰好执行一次。

**状态 bit2 (`ZERO_VALID`) 不能证明本次校零成功。** 它可能表示以前有效的零点；本次尝试失败时也可能仍为置位。当前上位机仅提示收到零点有效标志，并明确不能确认本次校零成功；该提示不得作为本次校准成功或可以安全运行的依据。需要另行可靠验证；无法验证时不应使能电机。

单播 ID 范围为 0～16；`0xFF` 仅支持广播 `DISABLE`。桥接板和驱动板也必须支持这些 ID才能实际控制。桥接板按 2.5 ms 槽位轮询，17 个槽位名义占用 42.5 ms；应答延迟、超时及调度等因素可延长实际周期，PC 的 50 ms 发送周期不保证每块都在 50 ms 内更新。

电机控制请求为 10 字节小端二进制帧：帧头 `0xA5`，电机 ID、命令号、序号、小端 IEEE-754 `float32` 参数和小端 CRC-16/CCITT-FALSE。位置参数的角度单位和传动比换算由驱动板协议决定；上位机发送滑块角度值，不在 PC 侧额外换算。

驱动板回传帧为 16 字节，帧头 `0x5A`，包含板卡 ID、序号、位置、母线电压、温度、状态和 CRC。串口线程接收 ID 在 0～16、CRC 正确且电压和温度为有限数值的回传，不限制其序号；因此迟到的有效回传也会更新显示，数值可能暂时回退。校零等命令的回调仍要求 ID 和序号与等待中的请求匹配，不能仅凭遥测更新确认命令执行；触觉帧仍交给原触觉解析器。回传位置字段按有符号 Q15 角度处理并使用 `180 / 32768` 度/计数换算；三个遥测值在对应关节卡片中实时显示。

## 4. 开发环境运行

需要 Windows 10/11、64 位 Python 3.10 或更新版本。首次运行需要联网安装 `requirements.txt` 中的依赖。在项目目录双击 `run_dev.bat`；也可以在 Windows 终端运行：

```bat
py -3.11 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python main.py
```

## 5. 编译为 EXE

在 Windows 项目目录双击 `build_exe.bat`。脚本检查 64 位 Python 3.10+ 和 `.venv` 中的依赖（缺失时安装），运行 GUI/协议测试，并从当前源码构建。构建成功后替换唯一的 `dist`；构建失败或目录被占用时保留旧版本，不另建备用 dist。替换前请关闭正在运行的上位机。首次构建需要联网安装依赖。

构建成功后生成单文件 EXE 和必要的 Qt Windows 平台插件：

```text
dist\PCMonitor.exe
```

请保留 `dist` 目录并整体复制到目标 Windows 电脑；其中 `PySide6\plugins\platforms\qwindows.dll` 是 Qt 平台插件。无需单独安装 Python。连接设备前请确认 USB CDC 驱动已安装且 COM 端口未被其他程序占用。程序设置保存在当前 Windows 用户设置中。

## 6. 测试与可清理的生成文件

- `test_motor_control.py`、`test_motor_protocol.py`、`test_serial_worker.py` 是测试源码，不会打进 EXE，但 `build_exe.ps1` 会在每次打包前运行它们；保留这些文件才能继续使用当前的自动测试构建流程。
- `.venv/` 是本机 Python 虚拟环境，不属于应用源码。删除可节省空间；之后运行 `run_dev.bat` 或 `build_exe.bat` 会重新创建并安装依赖。为方便日常修改和测试，建议本机暂时保留。
- `.pytest_cache/`、`__pycache__/` 是可自动重建的缓存，可以随时删除。
- `build/` 及其他 `build*` 文件夹是 PyInstaller 中间产物，可以删除，下次构建会重新生成。
- `dist/` 是已构建的 EXE 交付目录；如需直接运行或分发程序，请保留整个目录。旧的 `dist*` 备份/重复构建目录可以删除。分发时不要单独移动 EXE，需保留同目录的 `PySide6\\plugins\\platforms\\qwindows.dll`。
- `*.spec` 是 PyInstaller 可再生成的配置文件；当前构建命令不依赖手工维护的 spec 文件，可以删除。

项目内的 `.gitignore` 已忽略上述虚拟环境、缓存和 PyInstaller 生成目录，避免它们混入源码改动。

## 7. 文件说明

- `main.py`：页面切换、COM 连接、触觉和电机命令路由；
- `styles.py`：Qt 全局样式；
- `protocol.py`：79 字节触觉帧解析与校验；
- `serial_worker.py`：唯一的串口读写线程及共享流分帧；
- `widgets.py`：6×6 触觉热力表和传感板卡片；
- `motor_control.py`：17 电机滑块、批量命令、校零状态流程和位置调度；
- `motor_protocol.py`：电机命令编码、CRC、回传解析及触觉流分流；
- `test_motor_control.py`、`test_motor_protocol.py`、`test_serial_worker.py`：界面、协议、串口线程的回归测试；
- `requirements.txt`：运行和打包依赖；
- `run_dev.bat`：源码运行入口；
- `build_exe.bat`、`build_exe.ps1`：Windows EXE 构建入口。
